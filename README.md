# E-Commerce Web Application UI/UX Design

## 1. Project Overview

This project presents the UI and UX design of a modern **E-Commerce Web Application** developed using Figma. The interactive prototype demonstrates how customers can discover products, browse product categories, view detailed product information, manage their shopping cart, complete a secure checkout process, make payments, and track their orders through an intuitive and user-centred interface.

The design focuses on delivering a seamless online shopping experience by applying modern UI/UX principles, including visual consistency, simple navigation, responsive layouts, accessibility, and reusable design components.

Every screen was carefully designed to improve usability, reduce user effort, and provide a smooth purchasing journey from product discovery to order completion.

The prototype demonstrates how a modern e-commerce platform can provide an efficient, secure, engaging, and scalable shopping experience while maintaining a clean and professional interface.

## 4. Problem Statement

Many online shopping platforms contain complicated navigation, overcrowded interfaces, unclear checkout processes, inconsistent page designs, and limited accessibility support.

These problems may make it difficult for customers to find products, understand product information, complete payments, or track their orders. A confusing shopping process may cause users to abandon their carts before completing a purchase.

This project addresses these challenges by designing a clean, accessible, responsive, and user-friendly e-commerce interface. The proposed design simplifies the customer journey and allows users to move smoothly from product discovery to order completion.

## 7. User Flow Explanation

The application follows a clear and structured user flow.

### Step 1: Account Access

The user opens the application and chooses to:

* Log in to an existing account.
* Create a new account.
* Recover a forgotten password.

### Step 2: Home Page

After logging in, the user is directed to the Home page, where they can:

* View featured products.
* View product categories.
* Search for products.
* Access promotional offers.
* Navigate to other sections of the application.

### Step 3: Product Discovery

The user browses the Product Catalogue or selects a product category. Search and filtering options help the user find relevant products quickly.

### Step 4: Product Details

The user selects a product and views:

* Product images.
* Product name.
* Price.
* Description.
* Availability.
* Product specifications.
* Customer ratings or related information.

The user can then add the selected product to the shopping cart.

### Step 5: Shopping Cart

The Shopping Cart allows the user to:

* Review selected products.
* Change product quantities.
* Remove unwanted products.
* View the subtotal and total amount.
* Continue shopping or proceed to checkout.

### Step 6: Checkout

During checkout, the user provides or confirms:

* Personal information.
* Delivery address.
* Contact information.
* Delivery option.
* Order summary.

### Step 7: Payment

The user selects an available payment method and confirms the payment details.

### Step 8: Order Confirmation

After completing the payment process, the system displays an order confirmation containing the order details and reference information.

### Step 9: Order Tracking

The user can monitor the order status through the Order Tracking page.

### Step 10: Profile Management

The user can access the profile section to:

* Update personal information.
* Review previous orders.
* Manage account details.
* Track current orders.

## 8. Design Explanation

The design was developed using a user-centred approach. Each screen was created to help users complete tasks with minimal confusion and effort.

### Clean and Minimalist Interface

A clean interface was used to reduce visual clutter and help users focus on products, prices, actions, and important information.

### Consistent Visual Design

The same colour palette, typography, spacing, icons, buttons, cards, and form elements were used throughout the application.

### Clear Visual Hierarchy

Headings, product names, prices, buttons, images, and supporting information were arranged according to their importance.

### Simple Navigation

Navigation elements were placed in familiar positions so users could easily move between the Home page, catalogue, shopping cart, profile, and order sections.

### Reusable Components

Buttons, product cards, navigation bars, input fields, form controls, and other interface elements were created as reusable Figma components.

### Responsive Layout

Auto Layout and flexible spacing were used to support adaptation across different screen sizes.

### Clear Calls to Action

Important actions such as **Sign Up**, **Log In**, **Add to Cart**, **Proceed to Checkout**, **Pay Now**, and **Track Order** were presented using visible and understandable buttons.

### Simplified Checkout Process

The checkout process was divided into clear stages to reduce confusion and help users understand the information required before completing an order.

### Interactive Prototyping

Interactive prototype connections were created to demonstrate realistic navigation and user interactions between screens.

## 11. Accessibility Considerations

Accessibility principles were considered to make the application easier to use for a wider range of users.

The following accessibility considerations were applied:

* Used readable font sizes.
* Used clear and understandable text labels.
* Maintained sufficient contrast between text and backgrounds.
* Avoided relying only on colour to communicate important information.
* Used visible button states and clear calls to action.
* Provided adequate spacing between clickable elements.
* Used consistent placement of navigation elements.
* Created clearly labelled form fields.
* Used simple language for instructions and actions.
* Organised information using headings and sections.
* Used recognisable icons together with labels where necessary.
* Maintained a logical navigation sequence.
* Designed error and confirmation messages to be clearly visible.
* Considered different screen sizes when arranging content.
* Avoided overcrowding screens with unnecessary information.

## 12. Challenges Faced

During the project, the group experienced several challenges.

### Maintaining Design Consistency

Because different screens were designed by different group members, maintaining consistent colours, fonts, buttons, spacing, and components required regular review and coordination.

### Connecting Prototype Screens

Creating correct interactions between all pages required careful testing to ensure that buttons and navigation links directed users to the correct screens.

### Designing a Simple Checkout Flow

The checkout process needed to collect important customer, delivery, and payment information without becoming too long or confusing.

### Responsive Layout Design

Adapting content for different screen sizes required the use of Auto Layout, flexible containers, and consistent spacing.

### Organising Figma Components

Managing components, variants, icons, screens, and prototype connections became more challenging as the project increased in size.

### Balancing Visual Appeal and Usability

The group needed to create an attractive interface without adding unnecessary visual elements that could distract or confuse users.

### Accessibility

Selecting suitable colours, readable text sizes, visible buttons, and appropriate spacing required continuous review.

### Team Coordination

The group needed to divide tasks fairly while ensuring that all completed screens followed the same design system and user flow.

### Time Management

Designing, reviewing, testing, correcting, documenting, and preparing the final prototype within the available period required proper task planning.
